# prebuilt

Prebuilt, mostly statically linked, binaries of image, video, font, and PDF tools for Windows, Linux, and macOS: `zopfli`, `oxipng`, `pngout`, `ffmpeg`/`ffprobe` (built from source), the HEVC encoders `x265` (8, 10 and 12 bits) and `kvazaar` they are linked with, the libwebp tools `cwebp`, `dwebp`, `webpmux`, and `anim_dump`, the libavif tools `avifenc` and `avifdec`, the libjxl tools `cjxl`, `djxl`, `jxlinfo`, and `jxl_from_tree`, `jxl-oxide`, the HarfBuzz tools `hb-shape`, `hb-info`, `hb-subset`, `hb-vector`, and `hb-raster` (built with FreeType), the Google woff2 tools `woff2_compress`, `woff2_decompress`, and `woff2_info`, the OpenJPEG JPEG 2000 tools `opj_compress`, `opj_decompress`, and `opj_dump` (built without libpng, libtiff, and LittleCMS), the OpenJPH HTJ2K tools `ojph_compress` and `ojph_expand`, the OpenEXR tools `exrheader`, `exrinfo`, `exrmaketiled`, `exrmetrics`, `exrstdattr`, `exrcheck`, `exrmultipart`, `exrmultiview`, `exrenvmap`, `exrmakepreview`, `exrmanifest`, and `exr2aces`, with `exr-from-raw` and `exr-to-raw`, which write an EXR file from raw samples and dump the samples of one (see [below](#openexr)), `iso-jpeg`, the `jpeg` tool of the ISO JPEG reference codec (see [below](#iso-jpeg)), the libde265 decoder `dec265`, the libheif tools `heif-enc`, `heif-dec`, and `heif-info` (HEVC only, with x265 and libde265), `TAppEncoder` and `TAppDecoder`, the encoder and the decoder of HM, the HEVC reference software, and the PDF tools `qpdf`, `mutool` (MuPDF), and the Poppler tools `pdftoppm`, `pdftotext`, `pdffonts`, `pdfinfo`, and `pdfsig`, the veraPDF validator `verapdf`, `TestGrammar`, the checker of the Arlington PDF Model, `pdfium_test`, the command-line tool of PDFium (see [below](#pdf-tools)), and the barcode tools `zint`, `ZXingReader` (zxing-cpp), and `zbarimg` (ZBar) (see [below](#barcode-tools)).

The binaries are available from:

- [GitHub releases](https://github.com/meziantou/prebuilt/releases). Each release also contains `versions.json` (tool versions), `prebuilt-tools.json` (every file with its tool version, size, and SHA-256), and `build-keys.json` (the hash of what each build depends on: CI takes the binaries whose hash did not change from the latest release instead of building them again; running the workflow manually with `rebuild` builds everything).
- The [Meziantou.Prebuilt](https://www.nuget.org/packages/Meziantou.Prebuilt) NuGet package, which lists the tools and downloads them to a local cache:

  ```csharp
  string ffmpeg = await Meziantou.Prebuilt.PrebuiltTools.Ffmpeg.GetOrDownloadAsync();
  ```

  See [src/Meziantou.Prebuilt/README.md](src/Meziantou.Prebuilt/README.md) for details.

## iso-jpeg

`iso-jpeg` is the `jpeg` command-line tool of [thorfdbg/libjpeg](https://github.com/thorfdbg/libjpeg), the ISO JPEG reference codec: a JPEG (ISO/IEC 10918-1) encoder and decoder that shares no code with libjpeg-turbo, with arithmetic coding, 12-bit samples, and the progressive and hierarchical processes. `jpeg` says too little for a release file, so the files are named `iso-jpeg-<runtime identifier>` (`iso-jpeg-win-x64.exe`, `iso-jpeg-linux-x64`, ...).

- **Version**: libjpeg has no release tag, and the tool prints no version. It is built from a commit of the `master` branch, and its version is the last release of the `README.history` file at that commit followed by the commit: `1.72+702114c`.
- **License**: libjpeg is available under the GNU General Public License, version 3 or later, or under the ITU software license, which covers evaluation and conformance testing. Both texts are in its repository: [README.license.gpl](https://github.com/thorfdbg/libjpeg/blob/master/README.license.gpl) and [README.license.itu](https://github.com/thorfdbg/libjpeg/blob/master/README.license.itu). As for the other GPL tools (`ffmpeg`, `ffprobe`, `x265`), a release holds the binaries only, without the license files.
- **Exit code**: `iso-jpeg` exits with 0 when a conversion fails. It prints the error and leaves an empty output file, or does not touch it: a file that was there before the conversion can still be there. Delete the output file first, and check afterwards that it exists and is not empty, rather than the exit code. Only a command line it does not understand gives another exit code.

`iso-jpeg in.jpg out.ppm` decodes, and `iso-jpeg -q <quality> [options] in.ppm out.jpg` encodes: `-a` for arithmetic coding, `-v` for the progressive process, `-h` for optimized Huffman tables, `-z <mcus>` for a restart interval, `-s 1x1,2x2,2x2` for subsampling, `-c` for no color transformation, `-y <levels>` for the hierarchical process (with `-h`), and `-n` for a DNL marker. A PNM file whose maximum value is 4095 is encoded with 12-bit samples. Lossless encoding (`-p`) fails at this commit with "DQT marker missing".

## OpenEXR

The OpenEXR tools are built from the source tarball of the [OpenEXR](https://github.com/AcademySoftwareFoundation/openexr) release, with the libdeflate, zstd and OpenJPH it comes with and the Imath it pins, and compiled with `-ffp-contract=off` and without the SIMD code OpenEXR and OpenJPH choose at run time on x64, so that the lossy compressions decode the same samples on every runtime identifier.

- `exrheader`, `exrinfo`, `exrmaketiled`, `exrmetrics`, `exrstdattr`, `exrcheck`, `exrmultipart`, `exrmultiview`, `exrenvmap`, `exrmakepreview`, `exrmanifest`, and `exr2aces` (deprecated) are the utilities of the release.
- `exr-from-raw <description.json> <output.exr>` writes an EXR file from a JSON description of its header and files of raw samples: every compression and pixel type, subsampled channels, scan lines and tiles, every line order, mipmaps and ripmaps, deep scan lines and deep tiles, multi-part files, and any attribute, even a malformed one. `exr-to-raw [--header-only] <input.exr> <output-directory>` writes the header of a file as that JSON, with the offset tables and the bytes of every attribute, and its decoded samples as raw little-endian files, without any conversion. Their sources are `scripts/exr-from-raw.cpp` and `scripts/exr-to-raw.cpp`, and their formats are described in [src/Meziantou.Prebuilt/README.md](src/Meziantou.Prebuilt/README.md#openexr).
- OpenEXR and Imath are available under the BSD 3-Clause License, OpenJPH under the BSD 2-Clause License, libdeflate under the MIT License, and zstd under the BSD License.

The tests of each release write and read back files of every compression, pixel type, sampling, line order, level mode and part type, and check that the lossless ones give the samples back bit for bit and that the lossy ones decode the same samples on every runtime identifier.

## PDF tools

- **qpdf**: built from the release tarball with its native crypto provider only (no OpenSSL or GnuTLS), which implements every encryption variant of the PDF specification: RC4 40 and 128 bits, AES-128 and AES-256. It is linked statically with zlib and libjpeg-turbo (built without its SIMD code). Writing a file with RC4 encryption needs `--allow-weak-crypto`; reading one does not. qpdf is available under the Apache License 2.0 or the Artistic License 2.0.
- **mutool**: built from the MuPDF source release with the third-party libraries it ships (FreeType, HarfBuzz, libjpeg, OpenJPEG, jbig2dec, LittleCMS, ...), without X11, OpenGL, curl, libcrypto (no digital signatures) and Tesseract (no OCR). It has its built-in fonts, so `mutool draw` renders non-embedded base 14 fonts without any system font. MuPDF is available under the GNU Affero General Public License, version 3 or later. As for the other GPL tools, a release holds the binaries only, without the license files.
- **Poppler** (`pdftoppm`, `pdftotext`, `pdffonts`, `pdfinfo`, `pdfsig`): built from the Poppler source release with zlib, libjpeg-turbo, libpng, brotli, FreeType, LittleCMS 2, OpenJPEG, and NSS (for `pdfsig`), without the Qt, GLib and C++ wrappers, cairo, libcurl, libtiff, Boost, GPGME and HarfBuzz.
  - The font configuration is "generic" on every target, with no fontconfig and no Windows font lookup. A font a file does not embed is drawn only when the URW base 35 Type 1 fonts are in one of the Ghostscript font directories Poppler knows (`/usr/share/ghostscript/fonts`, ...); otherwise each tool prints a "No display font" configuration error per base 14 font and draws no text in that font. Without the poppler-data files, CJK text without an embedded CMap is not decoded.
  - `pdfsig` is not available for `win-x64`: NSS builds static libraries with its gyp build only, which targets MSVC on Windows. It links NSS statically, without the module of the built-in root certificates: without an NSS database (`-nssdir`), it prints "NSS_Init failed", still verifies the signatures, and trusts no certificate (`-nocert` skips the certificate check).
  - Poppler is available under the GNU General Public License, version 2 or later.
- **TestGrammar** (Arlington PDF Model): built from a commit of the master branch of [pdf-association/arlington-pdf-model](https://github.com/pdf-association/arlington-pdf-model), which has no release since 2021, with the copy of PDFium of the repository. Its version is the version of TestGrammar followed by the commit: `0.81+d148fee`. The release file is `TestGrammar-<rid>.tar.gz`, with `TestGrammar` (`TestGrammar.exe` on Windows), `LICENSE`, and `tsv/`, the TSV files of the model at the same commit: pass `--tsvdir tsv/latest`. It has no `--version` option, as the version is in the first line of its reports, and it exits with 0 whatever it finds: the problems are the `Error:` lines. The Arlington PDF Model is available under the Apache License 2.0.
- **veraPDF** (`verapdf`): the CLI of the veraPDF release installer, with a Java runtime cut with jlink from Eclipse Temurin, so that no Java needs to be installed. The release file is `verapdf-<rid>.tar.gz`, with the launcher `verapdf` (a shell script; `verapdf.exe` on Windows), `lib/verapdf-cli.jar`, and `runtime/` (with its `legal/` notices). The Linux runtimes need glibc. veraPDF writes its configuration to a `config` folder next to the launcher the first time it runs, and exits with 1 when a file is not compliant. veraPDF is available under the GNU General Public License, version 3 or later, or the Mozilla Public License, version 2 or later; the Temurin runtime under the GNU General Public License, version 2, with the Classpath Exception.
- **PDFium** (`pdfium_test`): built with the GN/depot_tools build of PDFium itself, from the `chromium/<N>` branch that [bblanchon/pdfium-binaries](https://github.com/bblanchon/pdfium-binaries) publishes, configured as the PDFium pixel tests are run (AGG renderer, no Skia, V8 or XFA), with the clang and libc++ Chromium downloads. Its version is that N. The release file is `pdfium_test-<rid>.tar.gz`, with `pdfium_test` (`pdfium_test.exe` on Windows), `LICENSE`, `test_fonts/` and `fonts/`, the fonts of the pixel tests: `pdfium_test --send-events --png --md5 --time=1399672130 --font-dir=test_fonts --croscore-font-names <file>.pdf` renders as `testing/tools/test_runner.py` does. The Linux builds are linked against the glibc of the Chromium Debian sysroot and need libgcc_s: they do not run on musl. linux-arm64 is cross-compiled, as Chromium ships its clang for x64 Linux machines only. PDFium is available under the BSD 3-Clause License, or the Apache License 2.0 for its newer files; the fonts under their own licenses (SIL Open Font License, Apache License 2.0, ...).

## Barcode tools

- **zint**: built from the release tag of [zint](https://github.com/zint/zint) with libpng and zlib, without Qt and without the GS1 Syntax Engine. It writes PNG, SVG, EPS, BMP, GIF, PCX, TIF and EMF files, and `--dump` prints the module matrix: one line per row, in hexadecimal, 4 modules per digit with the first one in the high bit, in groups of 2 digits, the last group with the digits the row needs only (`FE 5B F8` is the 21 modules `111111100101101111111`). `-b` selects the symbology (58 QR Code, 97 Micro QR, 145 rMQR, 20 Code 128, 8 Code 39, 25 Code 93, 10 EAN-8, 15 EAN-13, 34 UPC-A, 18 Codabar, 3 Interleaved 2 of 5, ...; `+12` or `+12345` after EAN/UPC data is an add-on), and `--vers`, `--mask` and `--secure` pin the version (or the Code 39 check digit, `--vers=1`), the mask and the error correction level. zint is available under the BSD 3-Clause License.
- **ZXingReader**: the reader of the example programs of [zxing-cpp](https://github.com/zxing-cpp/zxing-cpp), built from the release tarball with every reader and no writer, and with the stb_image of a pinned commit of [nothings/stb](https://github.com/nothings/stb). It reads PNG, BMP, GIF, JPEG, PNM and TGA files, not WebP. It prints the text, format, version, error correction level and mask (`Extra: {"DataMask":...}`) of each barcode; `-1` prints one line per barcode, `-json` the whole result, and `-symbol` the module matrix it sampled. It reports UPC-A as EAN-13 unless `-formats UPC-A`, reads EAN/UPC add-ons, and exits with 0 when it cannot load an image. zxing-cpp is available under the Apache License 2.0.
- **zbarimg**: the image scanner of [ZBar](https://github.com/mchehab/zbar), built from the release tarball with the symbologies ZBar enables by default (EAN/UPC, DataBar, Code 128, Code 93, Code 39, Codabar, Interleaved 2 of 5, QR Code, SQ Code: not Micro QR or rMQR), and statically linked with GraphicsMagick (PNG and zlib only: it reads PNG, BMP, GIF, PCX, PNM and TGA files, not JPEG or TIFF), and with GNU libiconv on Windows. `zbarimg -q file.png` prints `TYPE:text` lines, and exits with 4 when it finds no barcode. EAN/UPC add-ons are separate `EAN-2` and `EAN-5` symbols, read with `-Sean2.enable` and `-Sean5.enable`; UPC-A is reported as EAN-13 unless `-Supca.enable`.
  - ZBar is available under the GNU Lesser General Public License, version 2.1 or later ([COPYING](https://github.com/mchehab/zbar/blob/master/COPYING), [LICENSE.md](https://github.com/mchehab/zbar/blob/master/LICENSE.md)), GraphicsMagick under an MIT-style license, and GNU libiconv under the GNU Lesser General Public License, version 2.1 or later. As for the other tools, a release holds the binaries only, without the license files. The sources zbarimg is built from are the release tarballs of the versions in `versions.json` and `.github/workflows/ci.yml`, and `scripts/build-zbar.sh` builds zbarimg from them, so that it can be built again with a modified ZBar.

The tests of each release write the barcodes of `scripts/barcode-samples.sh` with zint, and check that ZXingReader and zbarimg decode them, with the version, error correction level and mask zint was asked for, and that the module matrix ZXingReader samples from a QR Code, Micro QR or rMQR PNG file is the one zint dumps.
